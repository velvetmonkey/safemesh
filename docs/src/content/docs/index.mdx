## What it does

Build a field inspection checklist that records answers on two devices without a
signal, then exchanges both answers for review after a connection returns.
[Fieldcheck](https://github.com/velvetmonkey/safemesh/tree/main/examples/fieldcheck)
shows this with a Rust application. You can also build a shared member list that
accepts edits while devices are apart, or count received units at a clinic and a
warehouse; the [two-app inventory demo](https://github.com/velvetmonkey/safemesh/tree/main/demos/two-app-inventory)
shows that count. The count is for units received, not units left in stock.

SafeMesh supplies the rules for combining those changes. It does not supply the
connection between devices, your data layout, or sign-in and access control.
A **merge** combines changes from separate copies. A **replica** is one device's
copy of the data. A **CRDT** is a data type whose copies can accept separate edits
and merge under a defined rule. See [how the rules work](/safemesh/concepts/).
This page follows **main (unreleased)**, rather than a release manual.

## Get a result

Follow [Get started](/safemesh/getting-started/) to save an edit, restart and sync
a second replica in a complete Rust or TypeScript program, from **main (unreleased)
source** you build yourself — no Lean build needed. Its stdout is checked by the
existing documentation CI job, so what you see is what the fixture actually prints.

Prefer to see failure handling first? Build and run the
[Rust break-it walkthrough](/safemesh/examples/) to partition, drop, duplicate and
reorder messages between replicas, then heal with anti-entropy and finish with
`CONVERGED=true`.

## Build your integration

Choose a Rust API layer by the storage and identity responsibilities you want it
to own — raw carriers, a caller-managed event log, or the Linux durable adapter —
or call SafeMesh from C ABI, WASM/TypeScript or Python.
[Use SafeMesh in your code](/safemesh/using-safemesh/) maps each language surface
to its ownership contract. For how the layers relate to the proof, see the
[architecture guide](/safemesh/architecture/).

## Evaluate the fit

SafeMesh's guarantees are conditional — on delivery eventually happening, on the
storage and platform assumptions your integration makes — and its v0 type
selection is a separate question from its proof status. Compare
[the limits](/safemesh/limits/) against your requirements before committing.

## Pick a data type

Choose by what a value must do when people edit it on separate devices. The
**G-Counter** only goes up; the **PN-Counter** goes up and down. The **G-Set**
only adds items and never removes them; the **OR-Set** adds and removes items.
Each OR-Set addition needs a fresh token, a unique marker for that addition.
If one device removes an item while another adds it at the same time, the new
add survives after a merge.

| Type | In plain words and an everyday example | Cannot do |
| --- | --- | --- |
| G-Counter | A total that only rises, such as units received at two warehouses. | Subtract units or show current stock by itself. |
| OR-Set | A shared list whose items can be added and removed, such as a team member list. | Make a removal win over a simultaneous new add. |
| G-Set | A shared list that only grows, such as IDs of visits already logged. | Remove an ID. |
| PN-Counter | A total that can rise or fall, such as the net change in one stock item. | Prevent two offline removals from overselling. |
| RGA/Text | An ordered list of entries, such as steps in a checklist. | Move an entry as one built-in operation; the caller supplies positions. |
| LWW Register | One value where the chosen timestamp decides which edit remains, such as a room label. | Preserve two competing labels. |
| Enable-wins Flag | An on/off value where a new simultaneous switch-on stays on, such as an alert toggle. | Make a simultaneous switch-off win. |
| LWW Map | Named values where timestamps decide each name's value, such as room names keyed by room ID. | Add competing numeric edits together. |

The last six types in this list are **Experimental** in the v0 table below.
The [concepts guide](/safemesh/concepts/#five-lean-backed-carriers) gives the
precise merge rules for the five Lean-backed types. [Limits](/safemesh/limits/)
explains where these choices do not fit.

<h3 id="v0-support">v0 focus</h3>

**G-Counter and OR-Set** are the two types selected for v0; **v0 focus** in the
table means this type selection, within the language-path limits below. All other
carriers remain **experimental**. The repository's source history records the
decision behind this selection; release status is a separate question from proof status, below.

Main is **unreleased**. Release artifacts and measured platforms are separate
from this selection; the [install matrix](https://github.com/velvetmonkey/safemesh/blob/main/README.md#install-matrix)
records their availability and evidence. Maintainer support is **UNKNOWN** for
all four language surfaces: this selection establishes no maintenance commitment.
Proof breadth and release support are separate: the five existing carrier proofs remain valid.

| Type | v0 status | Evidence |
| --- | --- | --- |
| G-Counter (`GCounter`) | **v0 focus** | [Lean model](https://github.com/velvetmonkey/safemesh/blob/main/lean/SafeMesh/DeltaGCounter.lean), [Rust conformance](https://github.com/velvetmonkey/safemesh/blob/main/rust/crates/safemesh-crdt/tests/conformance.rs) |
| OR-Set (`OrSet`) | **v0 focus** | [Lean model](https://github.com/velvetmonkey/safemesh/blob/main/lean/SafeMesh/DeltaORSet.lean), [Rust conformance](https://github.com/velvetmonkey/safemesh/blob/main/rust/crates/safemesh-crdt/tests/conformance.rs) |
| G-Set (`GSet`) | **Experimental** | [Proof and finite-test boundary](/safemesh/claims/#tested-not-proven) |
| PN-Counter (`PnCounter`) | **Experimental** | [Proof and finite-test boundary](/safemesh/claims/#tested-not-proven) |
| RGA/Text (`Rga`) | **Experimental** | [Proof and finite-test boundary](/safemesh/claims/#tested-not-proven) |
| LWW Register (`LwwRegister`) | **Experimental** | [Tested, not proven](/safemesh/claims/#tested-not-proven) |
| Enable-wins Flag (`EnableWinsFlag`) | **Experimental** | [Tested, not proven](/safemesh/claims/#tested-not-proven) |
| LWW Map (`LwwMap`) | **Experimental** | [Tested, not proven](/safemesh/claims/#tested-not-proven) |

These language paths have different limits:

- Rust: G-Counter and numeric/UTF-8 OR-Set mutation, record exchange and checked
  restore; only Linux Rust has the durable writer.
- TypeScript/WASM `SafeMeshOrSet`: numeric `add`, `applyRemove`, `contains`,
  `elements`, `merge`, `observedTokens`, and `tombstones`.
- TypeScript/WASM `SafeMeshStringOrSetReplica`: UTF-8 `createAllocated`,
  `appendAllocatedAdd`, `exportIdentity`, `importIdentity`, `appendAdd`,
  `appendRemoveObserved`, `mergeRecordBytes`, `mergeLogBytes`, `logBytes`,
  `versionFor`, `elements`, `observedTokens`, `tombstones`, `addEntries`, and
  `inspectRecordBytes`.
- Python: G-Counter mutation/exchange with caller-owned storage; numeric OR-Set
  mutation/remove/whole-state merge, without a UTF-8 replica or recovery promise.
- C: G-Counter carrier mutation/read and delta encoding, and numeric OR-Set
  mutation/remove/whole-state merge; no log or recovery promise.

The [install matrix](https://github.com/velvetmonkey/safemesh/blob/main/README.md#install-matrix)
records measured environments and artifact availability separately.
For decrementing stock, use [paired v0-focus G-Counters](/safemesh/getting-started/#decrement-with-v0-focus-types).
Application schemas, custom durable replicas and delivery/retry/storage remain caller-owned.
