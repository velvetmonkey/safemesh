# SafeMesh claims

Evidence labels apply to individual statements, including tested statements under the historical “Proven” heading. Evidence links name source artifacts; commands reproduce tests, not universal proofs. The site pins repository evidence links to its build commit.

SafeMesh's verified claim is deliberately narrow:

> In-house CRDT types backed by the Lean suite are provably insensitive to duplicate and reordered delivery, and convergent after missing deltas are eventually recovered by merge/anti-entropy. The Rust product body earns that claim only when it continues to pass the Lean-generated differential oracle corpus. **PROVEN** — Evidence: [`delta_dissemination_sec; merge_deltaState`](lean/SafeMesh/Delta.lean). **TESTED** — Evidence: [`conformance`](rust/crates/safemesh-crdt/tests/conformance.rs); run from `rust/`: `cargo test -p safemesh-crdt --test conformance --locked`.

## Proven

- The Lean delta suite in `lean/SafeMesh/` proves Strong Eventual Consistency for delta dissemination over the supported CRDT carriers. **PROVEN** — Evidence: [`delta_dissemination_sec; merge_deltaState`](lean/SafeMesh/Delta.lean).
- G-Set, G-Counter, PN-Counter, OR-Set, and RGA/Text have Rust implementations that are differentially tested against `tests/corpus.json`, emitted from the Lean definitions by `lake exe corpus`. **TESTED** — Evidence: [`conformance`](rust/crates/safemesh-crdt/tests/conformance.rs); run from `rust/`: `cargo test -p safemesh-crdt --test conformance --locked`.
- The Rust `EventLog` is a deduplicating append/merge/since/version infrastructure layer. Its admission decision, `admit_with`, transcribes the record-kernel model below and is tested against that model, not proven. It supports the product surface, but the proven convergence claim lives in the CRDT carriers and their Lean-backed corpus bridge. **TESTED** — Evidence: [`record_1_1_live_and_replay; duplicates_and_collisions_do_not_invoke_application`](rust/crates/safemesh-crdt/tests/record_admission.rs); run from `rust/`: `cargo test -p safemesh-crdt --features laws --test record_admission --locked`.
- The Lean record kernel in `lean/SafeMesh/RecordKernel.lean` (namespace `SafeMesh.RecordKernel`) is machine-checked on the same default build target and per-theorem axiom gate as the delta suite. Every theorem in it is about a model: a log, a cached live state, one admission transition, and the ownership facts a local writer is handed. `WHAT-IS-PROVEN.md` enumerates all 21 theorems and how each reaches Rust. The product claims that may be repeated from the kernel are the five below, and each carries the limit that must travel with it. **PROVEN** — Evidence: [`admission; checkedRestartSound`](lean/SafeMesh/RecordKernel.lean).
  - Record admission (`admission`, `idempotence`, `collision`): in every reachable modeled replica the log and the live state change exactly when a record is accepted; delivering the same record again changes nothing, however many times it arrives; and a different payload under an id already in the log is refused as a collision and mutates nothing, provided the log holds one payload per id. Limit: the theorem is about the modeled transition. The Rust `EventLog::admit_with` is a transcription held to it by Rust unit tests, not by the Lean oracle corpus, and decoding, authentication, version vectors and reporting a collision to a peer are outside the theorem. **PROVEN** — Evidence: [`admission; idempotence; collision`](lean/SafeMesh/RecordKernel.lean).
  - Replay agreement (`replayAgrees`, `collision`): every reachable modeled cache equals an independent replay of its log, and two reachable replicas whose accepted logs are equal have equal live state, whatever the delivery order and however many duplicates or rejections occurred. Limit: equal *accepted* sets, not equal input sets. When two payloads conflict under one id, arrival order decides which is accepted, so same-input-set convergence is not claimed. The model's transitions are atomic because they are functions; nothing here proves crash atomicity or storage durability in a running process. **PROVEN** — Evidence: [`replayAgrees; collision`](lean/SafeMesh/RecordKernel.lean).
  - Token ownership (`tokenDisjoint`, with `tokenOwner`, `tokenSequence`, `allocatedOwned`, `sequenceFresh`): under a fixed positive writer count, two distinct valid authors never mint the same token at any pair of sequences, one author never mints one token at two different sequences, allocation returns a token only for a valid author, a positive sequence and a value within the 64-bit bound; and a successful next-sequence step returns a strictly larger sequence that stays within the 64-bit bound. Limit: this is arithmetic on the `token` and `nextSequence` definitions. Whether a running process is the author it claims is a fact the local-filesystem shell supplies, and the Rust allocation is checked against a finite corpus. **PROVEN** — Evidence: [`tokenDisjoint; tokenOwner; tokenSequence; allocatedOwned; sequenceFresh`](lean/SafeMesh/RecordKernel.lean).
  - Ownership guard (`competingRefused`, `staleRefused`, `foreignCoordinateRefused`, `foreignTokenRefused`, `refusedUnchanged`, with `validPermitted`, `ownedWriter`, `ownedCoordinate`, `ownedReachable`, `ownedConvergence`): the modeled guard refuses a write when the lock is not held, when the generation is stale, when a counter coordinate is not the author's own, or when an add carries a token other than the one allocated to that author at that sequence; a refused write leaves log, live state and allocation mark unchanged; a permitted write is not refused; and guarded steps keep the replay-agreement invariant. The modeled guard is defined as the negation of the decidable `permitted` predicate, so exactly the permitted domain passes by that definition; no theorem concludes the converse, and `validPermitted` proves only that a permitted write passes. Limit: the guard decides on facts it is given, namely lock held, generation current and local write. It does not prove that an OS lock is exclusive or that a generation file was read correctly, and the Rust decision is tested over a finite corpus matrix. **PROVEN** — Evidence: [`competingRefused; staleRefused; foreignCoordinateRefused; foreignTokenRefused; refusedUnchanged; validPermitted; ownedWriter; ownedCoordinate; ownedReachable; ownedConvergence`](lean/SafeMesh/RecordKernel.lean).
  - Checked restart (`checkedRestartSound`, with `replayOwnedReachable`): when the modeled checked restart succeeds, the state it returns has a cache equal to replay of its log and an allocation mark equal to the saved one. The modeled restart is defined to fail on any history containing a refused or non-accepted record; the theorem speaks only about the successful case. Limit: the model receives an already-decoded history. It proves nothing about frame validation, lock reacquisition, file sync, rename or power-loss recovery, and the Rust restart path is Linux-only and held to the model by its own unit tests. **PROVEN** — Evidence: [`checkedRestartSound; replayOwnedReachable`](lean/SafeMesh/RecordKernel.lean).
- `LwwRegister` is tested-not-proven. It is a flat max-register over `(timestamp, replica, value)` and is covered by Rust laws/wire tests, but it is not in the current Lean oracle corpus. **TESTED** — Evidence: [`lww_register_wire_is_stable_and_roundtrips`](rust/crates/safemesh-crdt/tests/wire.rs); run from `rust/`: `cargo test -p safemesh-crdt --test wire lww_register --locked`. [Laws tests](rust/crates/safemesh-crdt/tests/laws.rs).

[Laws tests](rust/crates/safemesh-crdt/tests/laws.rs).
- `LwwMap` is tested-not-proven. It is a flat per-key LWW map with remove tombstones and is covered by Rust laws/wire tests, but it is not in the current Lean oracle corpus. **TESTED** — Evidence: [`lww_map_wire_is_stable_and_roundtrips`](rust/crates/safemesh-crdt/tests/wire.rs); run from `rust/`: `cargo test -p safemesh-crdt --test wire lww_map --locked`. ## Tested, not proven

- Rust code is checked against a finite Lean-generated corpus. Passing the corpus is strong conformance evidence, not a universal theorem about the Rust compiler or hardware. **TESTED** — Evidence: [`conformance`](rust/crates/safemesh-crdt/tests/conformance.rs); run from `rust/`: `cargo test -p safemesh-crdt --test conformance --locked`.
- Property tests and the `laws` feature harness test algebraic behavior over generated scenarios. They supplement the Lean-oracle differential test; they do not replace it. **TESTED** — Evidence: [`merge_laws_hold_for_in_house_samples; convergence_harness_hammers_delta_delivery_shapes`](rust/crates/safemesh-crdt/tests/laws.rs); run from `rust/`: `cargo test -p safemesh-crdt --features laws --test laws --locked`.
- Canonical wire encoding, binding glue, FFI, WASM, Python, demos, and storage or transport adapters are outside the Lean proof claim. For binding support facts, use the separate API present, artifact available, build checked, runtime tested, integration tested, and maintainer-supported statements in the root README; name the test environment rather than combining them into a single "tested" label. Transport adapters can be tested against the coverage contract, but SafeMesh does not prove network delivery. Bindings and adapters must call the Rust core rather than reimplementing merge semantics. **NOT COVERED** — Scope evidence: [proof boundary](WHAT-IS-PROVEN.md#the-honesty-boundary); binding evidence: [six support fields](README.md#install-matrix).
- Integrity vertical examples, including the cold-chain kill-test, are engineered evaluation artifacts. They test modeled software convergence; they do not prove sensor truth, legal custody, storage durability, or real transport delivery. **TESTED** — Evidence: [`cold_chain_kill_test`](rust/crates/safemesh-crdt/examples/cold_chain_kill_test.rs); run from `rust/`: `cargo test -p safemesh-crdt --examples --locked`.
- User-defined types are tested by their authors against the merge laws. SafeMesh does not prove arbitrary user reducers. **NOT COVERED** — Scope evidence: [author-supplied laws harness](rust/crates/safemesh-crdt/src/lib.rs).
- The Rust transcriptions of the record kernel are tested, not proven. The ownership guard, token allocation and sequence counter are replayed from the `ownership`, `allocation` and `sequence` sections of `tests/corpus.json`; `EventLog::admit_with` and the durable restart path are checked by Rust unit tests only. Passing these is conformance evidence over finite cases, not a theorem about the Rust code, the Linux filesystem, or the lock it relies on. **TESTED** — Evidence: [`conformance`](rust/crates/safemesh-crdt/tests/conformance.rs); run from `rust/`: `cargo test -p safemesh-crdt --test conformance --locked`. **TESTED** — Evidence: [`record_1_1_live_and_replay; duplicates_and_collisions_do_not_invoke_application`](rust/crates/safemesh-crdt/tests/record_admission.rs); run from `rust/`: `cargo test -p safemesh-crdt --features laws --test record_admission --locked`. **TESTED** — Evidence: [`restart_still_works_and_fresh_allocation; restart_invalid_history`](rust/crates/safemesh-crdt/src/local.rs); run from `rust/`: `cargo test -p safemesh-crdt --features laws --lib --locked`.

- Trees and ordered move semantics. **NOT COVERED** — Scope evidence: [assurance boundary](WHAT-IS-PROVEN.md#the-honesty-boundary).
- Leader election or consensus. **NOT COVERED** — Scope evidence: [assurance boundary](WHAT-IS-PROVEN.md#the-honesty-boundary).
- Guaranteed network delivery or radio-transport correctness. **NOT COVERED** — Scope evidence: [assurance boundary](WHAT-IS-PROVEN.md#the-honesty-boundary).
- Hardware puck behavior. **NOT COVERED** — Scope evidence: [assurance boundary](WHAT-IS-PROVEN.md#the-honesty-boundary).
- Storage durability, crash atomicity, or lock exclusivity as proven properties. The record kernel proves decisions over facts the local-filesystem shell supplies; the shell itself is tested. **NOT COVERED** — Scope evidence: [assurance boundary](WHAT-IS-PROVEN.md#the-honesty-boundary).
- Flag or Map as proven SafeMesh product types, unless matching Lean proofs and corpus-backed Rust conformance are added. `LwwRegister`, `EnableWinsFlag`, and `LwwMap` exist, but remain tested-not-proven until that proof bridge lands. **NOT COVERED** — Scope evidence: [assurance boundary](WHAT-IS-PROVEN.md#the-honesty-boundary).

## Wording rule

Use: "provably converges (once deltas are delivered)", "duplicate delivery does not duplicate modeled state", "machine-checked", and "re-runnable in your CI".

Do not use: "can't corrupt", "unbreakable", "guaranteed delivery", or "a faster Yjs".
